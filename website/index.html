0.2.14 · 一个入口，三种交付

先识别内容，再走真正属于它的流水线。

视频媒体与普通网页在进入处理链前就会分流。三类任务共用可恢复的阶段状态与任务归档，但不会把网页误送进视频逻辑，也不会用同一套产物冒充不同交付。

01 · SUBTITLEimplemented

双语硬字幕成片

面向 YouTube、Vimeo 与 X / Twitter 视频 URL，按来源选择获取方式；缺英文字幕时转入本地 Whisper。

  • 媒体格式与字幕 fallback 分开处理
  • 超过批次门槛时显示 cue 与批次数，等待成本确认
  • 每批译文独立持久化；重启后复用已验证批次
  • 校对后生成双语 SRT，再压制并用 ffprobe 验证
OUTPUT · bilingual.srt + burned video
02 · SUMMARYimplemented

有证据的视频总结

从字幕生成素材分析包，核验可外查的事实，再让三个隔离会话分别成稿、评分与融合；核验不可用时会明确标记。

  • 真实 research 阶段产出可追溯的外部证据账本
  • A / B / C 三稿独立生成，附六项评分与遗漏清单
  • 配图使用独立工具会话，不污染研究与写作上下文
  • 先选 Agent、验收封面，再逐张保存其余配图
OUTPUT · summary.md + images/
03 · DOCUMENTimplemented

结构保真的网页文档

把普通网页与支持的单条 X 内容清洗为 Markdown，可仅转换，也可选择 normal 或 refined 翻译并进入双栏校对。

  • 静态图片本地化，结构完整性不通过就退回校对
  • 长文按批翻译并保存进度，refined 增加精修与终检
  • 四个视觉方向独立预览，不覆盖 Markdown 权威产物
  • 发布为可离线打开、资源内嵌的单文件 HTML
OUTPUT · Markdown + standalone HTML
可检查，不靠猜

长任务的关键状态，都有落点。

Etch /etʃ/ 是“刻蚀、镌刻”。这里不只指把字幕压进画面，也指把来源、阶段、人工决定与最终产物留在任务记录里。

Local-first

下载、转写、文件管理、字幕生成与压制在本机完成；翻译数据是否离开设备取决于你选择的 Agent CLI。

阶段与批次可恢复

异常退出后从 task.json、durable run registry 和已提交产物恢复；字幕与长文翻译会逐批保存，不必从头重跑。

术语一致

新任务参考历史视频术语表；术语修改可先预览影响到的 cue，再一次性应用到全部译文。

Provider 可替换

支持 Claude、Codex、Qoder、OpenCode 本地 CLI，不绑定单一 SDK，也不依赖常驻服务。

人工 checkpoint

翻译成本、字幕歧义、文档校对、外部核验与配图 Agent 等关键决定，会停下来等待明确选择。

任务分类

为字幕、总结与文档任务设置自定义分类；分类只是归档，不会改写任务流水线或阶段状态。

v0.2.14 源码 · 可选投稿 sidecar

成片验证通过，
直投 B站。

使用具备投稿权限的 B站账号扫码连接。Etch 只让验证通过的成片进入本地投稿队列；每次提交前，你仍然掌握标题、分区、标签、简介、版权类型、转载来源与封面。此能力已进入当前源码，公开 v0.1.2 安装包尚不包含。

01
手动确认，或默认关闭的自动投稿新建任务时可按需开启；账号、默认分区和标签不完整时不会误启用。
02
凭据由 macOS 安全存储加密投稿时由本机内置 biliup 直连 B站，不经过 Etch 自建云端或中转服务。
03
只有可验证回执才标记成功若提交结果无法确认，Etch 会要求先到创作中心核对，再决定后续动作。
01 · CONNECT扫码连接账号

读取投稿分区，配置默认标签与简介模板。

02 · REVIEW确认投稿信息

URL 任务默认按转载处理，并自动带入来源。

03 · UPLOAD加入本地单并发队列

上传阶段可以停止，之后从 Etch 重新发起投稿。

04 · RECEIPT保存可验证回执

取得 aid、BV 号等回执后，才显示已提交。

V1 边界单账号、单投稿并发；不支持定时、多账号、审核轮询或远端稿件管理。提交成功后，请到 B站创作中心查看审核状态。
